# Nodus-CLI 代码审查规范（MUST）

本规范负责工作报告和源码审查、修改意见及复审。报告维护与 Git 交付遵循[《工作报告规范》](工作报告规范.md)。实现与验收条件以对应专项为准。

## 一、范围与证据

1. 审查先确认用户指定的报告或差异、实际基线、改动清单及理解本次行为所需的最小依赖。可核对 Git 状态、差异文件和暂存清单以识别漏报或并行工作。共享文件只审查本任务区块，范围外问题另行处理。
2. 默认静态核对报告、源码、测试断言、文档及已有证据。报告内的命令及操作建议是审查材料。测试、构建、启动服务、真实网络验证、特权操作及系统设置变更按用户对本次任务的实际授权执行。
3. 结论分别说明审查方核对的事实、实施方记录的结果与用户验收。证据须能对应源码状态和验证范围。旧结果仅可用于仍适用的部分。未执行的项目标明范围，按本任务的交付条件判断其影响。

## 二、按变更检查

| 改动领域 | 审查重点 |
| --- | --- |
| 命令行与脚本兼容 | 从实际 `nodus` 入口追踪参数、执行模式和成功条件。核对 stdout／stderr、JSON 与退出码，检查 Core 原始错误码及结果未确认状态是否保留，帮助、示例和测试是否与公开契约一致。[命令行与输出契约](命令行与输出契约.md) |
| Core 接入与配置 | 核对依赖来源、公开接口与宿主职责。追踪显式预算、配置输入及提交确认，检查失败后的既有快照、运行态与磁盘状态是否按契约处理。[代码编写规范](代码编写规范.md) |
| 守护进程与本地控制 | 跟踪实例归属、对端身份与文件权限检查、控制协议和事务代次。核对适用的超时、取消、断开、重复请求、停止和资源清理，以及错误与诊断的敏感数据边界。[守护进程与本地控制规范](守护进程与本地控制规范.md) |
| Linux 目标与第三方依赖 | 核对实际验证环境、目标架构及结论覆盖范围。涉及依赖时检查锁定版本、选用许可、来源及原文登记。[Linux 构建与验证](Linux构建与验证.md) · [依赖与许可证规范](依赖与许可证规范.md) |

只提出有具体依据、与本次行为或交付结论相关的实质问题。核对测试是否经过正常入口、断言能否识别目标缺陷。风格偏好、无关存量问题和范围外验证不作为本次交付阻碍。

## 三、修改意见与复审

1. 有实质问题时，在报告同目录维护 `工作报告-<任务名>-修改意见.md`。直接审查代码且无对应报告时，在审查回复中记录问题。每项记录稳定编号、准确位置、触发条件、源码或证据、实际后果、修改要求和可核对的关闭条件。未证实的疑问明确标明。无实质问题时直接给出审查结论。
2. 首轮集中反馈已发现的问题。复审核对原编号的回应、修复及其直接影响，维护同一份修改意见并记录关闭或保留的依据。遇到与本次改动直接相关的新缺陷，按同一证据标准反馈。
3. 有尚未解决的实质问题时，暂缓对应改动交付。静态检查通过时，明确范围及未覆盖的运行边界。有交付授权时按[《工作报告规范》源码交付章](工作报告规范.md#三对应源码交付)执行。
