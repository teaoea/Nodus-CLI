## 二、Core 与宿主的职责

1. Nodus-CLI 是 Nodus Core 的 Linux 宿主。CLI 负责命令解析、启动与控制编排、Linux 进程与文件资源、用户授权、预算输入以及结果呈现。协议、路由、DNS、会话、资源计量与配置提交语义委派给 Core 的公开 Rust 接口。Core 尚未提供的能力明确返回不可用，或在 Core 仓库完善后接入。禁止通过访问内部状态、复制网络管线或临时填充值绕过接口。
2. 维持单个 `nodus` 二进制。进程启动入口完成装配，命令层处理参数与呈现，守护进程协调请求，Core 接入层将宿主意图转换为受约束的 Core 调用。离线命令复用适用的 Core 校验入口。仅在有实际调用者或需要隔离现有职责时拆分模块。
3. 使用 Rust Edition 2024，并在本仓库 Rust crate 禁止 `unsafe`。平台调用使用有安全接口的依赖。通过 `Cargo.lock` 与依赖声明固定可追溯的 Core 来源、版本或提交及所需 features；本地路径联调须记录来源提交及是否含未提交改动，正式构建须能从干净检出重现依赖来源。新增依赖前核对实际用途和 Linux 目标兼容性，许可准入遵循[《依赖与许可证规范》](依赖与许可证规范.md)。
4. 启动时从显式启动参数或部署配置取得预算，记录限额的对象、单位、来源及超限行为，经 Core 校验并完整传入。缺失必要预算、单位非法或溢出时启动失败。任何有效默认值与新硬上限应有已确认的依据；CLI 不擅自用无限额度、静默截断或另建业务预算替代 Core 契约。展示时区分 Core 计量与进程 RSS。

## 三、配置文件和编程边界

1. CLI 负责其受管配置、资源和目录的定位、权限核验及显式文件操作。向 Core 交付已授权的绝对路径和必要的只读资源引用。来自配置正文、订阅或 IPC 的路径不得自行扩展文件访问范围。外部输入文件保持只读，除非命令明确授权修改其目标。由 CLI 管理的持久化替换使用同文件系统的原子发布，并按承诺处理同步、权限和失败。
2. 将参数解析、输入校验及结果转换与 I/O 分开。默认最小可见性，模块通过明确接口协作。状态、单位及错误使用能表达语义的类型；生产路径将无效输入和可恢复失败作为正常错误返回，避免以 `unwrap`、`expect` 或 panic 代替处理。
3. 活动任务、Socket、文件和共享状态须有明确所有者。同步锁不得跨异步等待或阻塞 I/O。说明资源的作用域、停止入口和释放完成条件，取消等待不能提前释放仍被实际工作使用的资源。守护进程的具体契约见[守护进程与本地控制规范](守护进程与本地控制规范.md)。
4. 使用 Rust 格式化约定。清除本次涉及且已确认无生产用途的代码，核查受支持目标及公开入口后再删除。公开行为变更同步帮助、契约和受影响的使用示例。

## 四、注释与文档注释

1. 说明性注释用中文，保留准确的 Rust、Linux 和协议术语。用 `//!` 说明模块职责、边界与主要调用关系；用 `///` 记录公开接口及具有调用约束的内部接口；用 `//` 解释局部实现中的设计原因。为有助于理解的内容写注释，避免逐行复述代码。
2. 接口文档按实际影响说明输入前提、成功条件、失败后果及副作用。命令和控制入口说明执行方式，以及返回时对应的是校验完成、操作已提交还是结果已确认生效。命令参数、退出码及 JSON 字段的完整契约见 [CLI.md](../CLI.md)，源码注释引用相关章节。
3. 文件与 Socket 权限、凭据、预算、并发及取消等关键约束写在对应实现附近。说明所有者、不变量、设计依据、由谁核验、何时生效以及失败后保留的状态。涉及预算交付时，分别写清 CLI 已完成的输入校验和 Core 实际接受的限额。
4. 接口、错误路径、权限或资源生命周期变化时，同步更新或移除受影响的注释。注释描述当前行为，阶段计划记入 [TODO.md](../TODO.md)，实测结果记入对应工作报告或验证证据。注释和示例使用脱敏数据，禁止记录凭据、私钥、令牌或真实用户数据。
