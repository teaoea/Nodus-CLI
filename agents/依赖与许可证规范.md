# Nodus-CLI 依赖与许可证规范（MUST）

## FUCK GPL、LGPL、AGPL、MPL、EPL、CDDL 及其他 Copyleft 许可证

本规范负责 Nodus-CLI 第三方库的许可证准入、来源登记、升级及整改。Nodus-CLI 自有代码的许可证见 [LICENSE](../LICENSE)。

## 一、许可准入

1. **仅允许以经核实的宽松许可引入第三方库。禁止采用 GPL、LGPL、AGPL、MPL、EPL、CDDL 等许可证的任何版本，以及其他具有 copyleft 或附带源码提供、同许可分发义务的许可。** 文件级、库级及网络交互触发的互惠条款同样适用。常见可准入许可包括 MIT、Apache-2.0、BSD-2-Clause、BSD-3-Clause、ISC 和 Zlib。引入时须满足所选许可证实际要求的声明、署名及其他义务。
2. 规则覆盖直接与传递依赖、可选及目标专用依赖、构建和测试依赖、原生库、随源码纳入的第三方实现，以及经 Core 引入的第三方库。静态链接、动态链接、当前未启用的 feature 或当前未构建的目标均不构成豁免。审查应覆盖仓库声明的项目依赖及其实际来源，区分项目纳入的库和开发主机单独提供的通用工具。
3. 对多重许可按实际可选条款判定。表达式含 `OR` 时，必须有一条覆盖所用代码的合规路径，并登记实际选用的许可。例如 `MIT OR GPL-3.0-only` 可在确认所用版本和全部相关文件均受 MIT 覆盖后按 MIT 准入。表达式含 `AND` 时，必须满足同时适用的全部条款，例如 `MIT AND GPL-3.0-only` 禁止引入。表达式含 `WITH` 时，核对基础许可证和例外全文；禁止采用的基础许可证不因链接或其他例外取得准入。组合表达式遵循括号和运算符优先级。参见 [SPDX 许可表达式](https://spdx.github.io/spdx-spec/v2.3.1/SPDX-license-expressions/)。
4. 许可缺失、条款不明、元数据与原文冲突、或无法确认选用许可覆盖实际所用文件时，暂缓引入。包管理器的许可字段用于定位和交叉核验，准入依据为锁定版本随附的许可证、声明及涉及文件的授权。

## 二、登记、升级与验证

1. 新增依赖、升级版本、替换来源或变更 features 和目标依赖时，检查变更后的依赖图及新增传递来源。以锁定依赖与构建配置核对版本或提交、来源、原始许可表达式、实际选用的许可及适用范围。原生和随附代码应单独核对其许可证。Cargo 元数据与依赖图检查不能替代对许可原文的核对。
2. 引入时登记组件、版本或提交、来源、所选许可及原文出处，并随源码或分发物按条款保留所需许可证原文、版权声明及 NOTICE。依赖许可登记与项目自身的 MIT 许可分别维护。
3. 候选版本或新引入的传递依赖违反准入规则时，阻止该变更，记录组件、依赖链和冲突条款。既有依赖发现不合规时，记录影响版本与使用范围，按任务范围移除或替换；受影响的产物不得交付，直至复核通过。构建和功能验证见[《Linux 构建与验证》](Linux构建与验证.md)。
