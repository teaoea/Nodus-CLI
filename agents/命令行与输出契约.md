# Nodus-CLI 命令行与输出契约（MUST）

本规范负责 `nodus` 的用户接口及脚本可观察行为。守护进程的控制协议、权限及事务由[守护进程与本地控制规范](守护进程与本地控制规范.md)定义。

## 一、命令与参数

### 命令设计

1. 按用户操作的对象和意图组织命令，复用同类操作的命名。新增子命令用于独立的操作；选项用于限定实例、对象范围或调整同一操作的参数。别名与正式名称具有相同语义和权限。
2. 定义命令是离线执行、控制已有实例还是启动实例，并明确作用对象、权限、成功条件和副作用。查询、检查和变更的边界须在命令名或语法中可辨认。同一入口兼有查询与变更时，由明确的参数决定行为，并分别登记。涉及磁盘与运行态的变更须说明返回时各自的完成状态。
3. 全局选项只用于多个命令共享的意图。登记可用位置、适用命令、默认值及来源，并区分接受参数、完成前置校验和实际生效。

### 命令登记与解析

1. 每个公开命令登记命令名、别名、参数、默认值及其来源、冲突规则、执行模式、权限、副作用、成功条件和失败表现。当前实现登记及规划见 [CLI.md](../CLI.md)。帮助、示例、实际解析和可观察行为须一致。
2. `--config` 表达配置输入，`--socket` 表达控制端点。显式值优先于已文档化的默认来源。显式值无效时返回错误，禁止静默切换到其他配置或实例。启动、离线与在线命令应在帮助中说明各参数何时适用。
3. 离线 `config check` 不依赖守护进程或控制 Socket。公开在线校验、状态查询和控制命令须按文档连接指定实例。实例不可达时返回实际错误，禁止擅自启动进程或切换离线模式。查询行为除了其契约约定的读取或探测，不得改变运行配置。
4. 人类界面可本地化。自动化须依据公开参数、退出码与机器字段，禁止把人类消息、表格布局或颜色当作控制协议。
5. 命令按完整实现、仅前置校验和规划登记。帮助的可用命令清单只列能够完成其公开操作的命令；部分实现的入口可独立说明已完成的边界。显式调用已识别的未启用能力时，适用的前置检查通过后返回 `Unsupported`，参数或权限检查失败时保留对应原因。无法识别的命令按用法错误处理。规划示例注明对应阶段。

## 二、输出与退出状态

1. 查询与控制命令支持 `--json` 和默认人类可读输出。人类模式在 stdout 输出结果，在 stderr 输出错误、警告与进度。JSON 模式下，单次命令在 stdout 输出一个 UTF-8 JSON 结果，成功和失败都有文档化的结构。解析阶段识别出有效的机器模式请求后，参数错误也使用该模式。日志、进度、颜色与弃用提示不得污染 JSON stdout。若提供持续输出命令，发布前须单独定义记录边界与终止语义。
2. 机器契约须定义成功与失败的判别字段、结果数据、错误来源及机器代码，逐项说明字段类型、单位、空值和缺省含义。空集合、真实零值、暂不可观测和操作失败各自表达。数据顺序有业务含义时明确排序。解析器不得依赖人类消息判断状态。
3. 退出码分类、宿主错误标识、Core 错误保留以及操作结果与输出失败的映射，统一遵循[《错误代码规范》](错误代码规范.md)。具体公开退出码和 JSON 字段见 [CLI.md](../CLI.md)。

## 三、兼容与弃用

1. 公布稳定版本时记录版本、来源提交和承诺的命令、参数、退出码、JSON 字段及可观察行为。实验接口明确标识并保持当前帮助、示例和测试一致。
2. 已实现命令随源码登记当前行为，稳定发布时以明确列入承诺的范围建立兼容基线。对稳定契约，删除或改名、改变字段类型或语义、改变退出码含义，以及改变默认值导致既有调用行为变化，均须按不兼容变更处理。弃用时登记旧用法、首次弃用版本、替代入口及迁移示例，在正式获准移除前保留受承诺的有效行为。新增字段须保持已发布消费者契约，消费者应忽略未识别的可选字段。
3. 命令与输出变更的回归按[《测试规范》](测试规范.md)执行。
