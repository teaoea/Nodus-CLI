# Nodus-CLI 守护进程与本地控制规范（MUST）

本规范负责 L1 用户态守护进程、进程间控制、运行态配置变更和敏感数据处理。模块与宿主职责见[代码编写规范](代码编写规范.md)，用户可见的错误呈现见[命令行与输出契约](命令行与输出契约.md)。

## 一、实例与权限

1. 每个控制端点对应一个运行实例。守护进程持有该实例唯一活动的 Core、控制监听器及其宿主任务。仅在必要初始化成功且可受理操作后报告就绪。启动失败时回收本次已取得的资源，保留主失败和清理失败。
2. L1 以普通用户执行 `nodus run`。控制端点为文件系统 Unix Domain Socket。默认端点位于该运行用户独占的目录。自定义路径同样必须经所有者、目录访问边界、对象类型与链接检查。以受保护的目录和创建方式确保 Socket 自出现起即为 `0600`，禁止短暂暴露可访问端点后再补权限。
3. 守护进程从内核 `SO_PEERCRED` 读取实际对端 UID，并要求其与守护进程有效 UID 一致。控制客户端在发送请求前也需核验对端 UID。缺失或不符即拒绝，路径可达、请求自报身份均不能代替凭据。L1 信任范围是同 UID 进程，不提供跨 UID 管理或远程控制。
4. 启动与清理用互斥所有权协调。遇到已运行实例、未知所有者、普通文件、符号链接或无法确认归属的端点时，拒绝接管。仅在持有互斥所有权并核实端点归属与状态后清理自己的残留 Socket。退出删除前确认仍为本实例创建的对象。
5. 每个受理操作检查其权限、实例状态及适用 Core 能力。CLI 的普通控制入口不得转发 Core 私有接口或绕过 Core Debug 等专用控制的授权。

## 二、控制协议和请求结果

1. 请求／响应协议独立于 `--json`，必须定义消息边界、协议版本、操作、请求标识、实例代次及适用的事务结果。协议不兼容、非法消息、无效字段和过期实例代次须明确拒绝。变更协议时同步版本与受支持的客户端／守护进程组合，禁止在未确认兼容时执行操作。
2. 实现必须明确帧、连接、在途请求及等待的有效边界与超限行为。读取正文和分配前验证长度，解析后再授权并执行；异常输入只影响所属连接或操作。资源硬上限的设定遵循[代码编写规范](代码编写规范.md)。
3. 定义操作何时可取消，以及取消与提交竞争时如何判定结果。客户端断开或超时只表明确认缺失，不能据此推断未执行。已提交操作按实际结果处理。可重试变更需有明确的幂等契约或可靠的状态查询，禁止在结果不明时自动重复有副作用的请求。

## 三、配置事务和进程生命周期

1. `config apply`、`config reload` 和 `SIGHUP` 涉及运行态变更时复用同一校验和提交路径。对同一实例协调变更，明确来源文件及准备所使用的代次，并在提交时核对目标仍有效。候选配置交由 Core 校验，由 Core 原子发布。
2. Core 确认提交后才报告运行态生效及其确认的代次。候选失败保留当前有效快照，保持既有连接按 Core 契约运行。命令如果承诺持久化，须另外跟踪并确认文件发布结果，声明运行态与磁盘状态不一致时的恢复行为。一次失败不得掩盖另一步骤已完成。
3. `SIGINT`、`SIGTERM` 与常规停止走同一条可重复调用的清理路径。停止接收新变更，协调正在运行的请求，然后调用 Core 明确的会话关闭入口并等待必要资源实际释放，完成宿主任务退出、日志刷盘和本实例端点清理。关闭请求和关闭完成必须可区分。清理失败如实报告，进程被强制终止不视为已完成清理。
4. `SIGHUP` 仅对支持热加载的活动实例提交重载意图。进入停止流程后拒绝新重载，已开始的操作依据其提交状态结束或取消。不得以销毁句柄、任务分离或固定延迟替代完成确认。

## 四、密钥与受控诊断

1. 秘密值仅从符合权限要求的私有文件或明确配置的受控环境变量读取。文件须为运行 UID 所有的 `0600` 普通文件，从受保护的目录安全打开，拒绝符号链接并核验实际打开对象。主 YAML 可包含经授权的引用，不含私钥、PSK、认证令牌等秘密原文。禁止以命令行参数传秘密，禁止向子进程无意传播敏感环境变量。
2. 缩短凭据存活时间，减少复制，使用 `Zeroizing` 或项目认可的等效机制托管适用缓冲区。秘密值及其可逆表示不得进入命令输出、日志、诊断或错误回显。调试日志与导出也须遵循同一边界。
3. 查看和导出日志使用 Core 支持的 NODLOG2 接口，保留其加密与权限语义。新导出文件使用适当的私有权限，结构化诊断只包含契约允许的字段。处理失败时保留可安全公开的操作、原因、原错误码和关联信息。
