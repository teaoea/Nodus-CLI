# Nodus-CLI 工作报告规范（MUST）

本规范负责工作报告的编写、维护与对应源码交付。审查及修改意见遵循[《代码审查规范》](代码审查规范.md)。构建与运行证据按[《Linux 构建与验证》](Linux构建与验证.md)记录。

## 一、存放与维护

1. 有独立交付范围的实现或缺陷修复，使用一份 `.local/reports/工作报告-<任务名>.md`。同一任务持续更新原报告。简单改动可简写，按实际影响记录。仅审查、分析或维护规范时，无需另写实施报告。
2. 每份报告覆盖一项任务。合并交付时保留各任务的范围、必要依赖和提交顺序。共享文件按函数、类型或文档区块列明本次改动。
3. 原始日志及机器可读验证记录保存在 `.local/test-evidence/` 或本次明确指定的本地位置，报告引用必要证据。命令、配置片段及日志须脱敏，凭据、私钥、认证令牌和真实用户数据禁止进入报告与交付材料。临时证据缺失时注明实际情况。

## 二、报告必备内容

| 项目 | 记录要求 |
| --- | --- |
| 当前状态与基线 | 任务名、作者、更新时间、CLI 实际基线提交、工作区状态及必要的 Core 依赖来源。开发与验证基线不同则分别记录。开头说明已实现行为、待验证或待修复事项及提交建议。 |
| 目标与验收标准 | 说明任务目标、适用条件、改动前后行为及可观察的成功与失败结果。区分用户要求和实现选择。 |
| 改动与依赖 | 列明新增、修改、删除和移动的路径，以及对应符号或区块、原因、依赖任务和范围外保留内容。移动同时记录旧路径和新路径。涉及公开命令或控制协议时说明兼容影响和对应文档、示例、测试。 |
| 验证与限制 | 记录实际命令或操作、目标与过滤范围、环境、结果、退出码及证据位置。按适用范围给出实际 Core 版本或提交、Rust 工具链、target 和 features。明确失败、跳过、未执行及有影响的重试，并说明验证对应的代码状态。 |
| 剩余事项与复审回应 | 分别说明已确认缺陷和未验证范围。按修改意见的编号更新原报告，记录处理方式、源码位置、已有证据及当前状态。 |
| 拟提交范围与说明 | 给出可直接使用的中文提交标题和必要正文，明确文件或区块范围、必要依赖及保留的其他改动。简单任务可注明无需补充正文。提交建议与用户实际授权分别记录。 |

本次新增[最简实现条款](代码编写规范.md#最简实现must)所列额外步骤时，在改动说明中定位该步骤，记录对应验收条件、核对依据及省略后的实际影响。同一依据适用于多个步骤时可合并说明。

影响 `nodus` 命令时，按实际变更说明输入、stdout／stderr、JSON 字段及退出状态。涉及守护进程时，说明操作返回时已确认的状态，尤其是配置生效、结果未确认、取消及关闭完成。已有检查按静态核对、编译、Linux 实际运行、最低基线和真实网络验收分别记载。开发主机、替身或交叉构建的结果只用于其实际覆盖范围。用户验收注明确认日期、代码状态及明确确认的范围。

## 三、对应源码交付

1. 按用户实际授权分别提交、推送、部署或发布。报告建议、测试命令及审查通过本身不授予这些操作权限。
2. 提交前核对当前基线、待交付文件与区块、暂存内容及依赖。保留并行任务改动。工作报告、修改意见、临时证据、凭据、用户数据与构建产物均留在本地。推送前核对将推送的提交与目标仓库及分支。
3. 提交后核对提交内容，推送后核对目标引用。交付记录标明实际提交和已完成的操作。按用户授权清理已完成用途的对应材料，保留未完成任务的报告及必要证据。
