# Nodus CLI 测试规范（MUST）

本规范负责测试设计、注册、断言和结果判定。文件归属见[《目录结构与文件归属规范》](目录结构与文件归属规范.md)，构建命令、目标平台和实际运行条件见[《Linux 构建与验证》](Linux构建与验证.md)。审查与执行授权遵循[《代码审查规范》](代码审查规范.md)。

## 一、范围、注册与断言

1. 按公开行为和实际改动选测试。优先复用能识别目标缺陷的用例。新增或修改的行为须有可独立判断的预期。缺陷修复应覆盖原失败条件并验证预期结果。
2. 纯逻辑可用单元测试，跨模块行为通过生产入口做集成测试。对调用方可见的 CLI 契约，使用 Cargo 提供的二进制路径或明确记录的对应构建产物启动真实 `nodus` 进程。检查进程退出码、stdout 和 stderr，机器模式还应解析结果结构并核对字段与语义。
3. 测试由 Cargo 按项目清单实际发现。新增、移动或删除测试时，同步受影响的目标、过滤条件、夹具与说明。保持生产接口的可见性边界，测试按公开契约或受控内部接口执行。
4. 断言依据已确认的契约或独立预期。按影响核对失败来源、状态及副作用，包括操作未执行、已提交但确认缺失、失败后保留的配置和实际释放的资源。错误映射断言见[《错误代码规范》](错误代码规范.md)。

## 二、隔离与真实验证

1. 测试使用脱敏样本、独立临时目录和非生产实例。使用独立 Socket、端口及临时配置，清理由本轮创建的子进程和文件，覆盖成功、失败与取消路径。会改变进程全局预算或环境的用例优先使用隔离子进程。
2. 并发测试优先用屏障、通道或明确等待点建立时序，使用超时约束挂起。替身用于控制输入、时序和失败。结论限定于实际经过的生产行为与边界。
3. 真实 Linux 系统行为按[《Linux 构建与验证》](Linux构建与验证.md)核验。需要真实远端、外部服务、特殊权限或改动系统网络状态时，按当前任务授权使用受控测试环境。

## 三、结果与证据

1. 记录实际命令、target、features、过滤条件、系统与架构、Rust 工具链、适用配置、源码与 Core 依赖状态、真实退出码和结果。修改影响测试结论的源码或依赖后，注明旧结果对应的版本。重试保留必要的失败原因与结果。
2. 区分通过、失败、跳过和未执行。构建失败时注明用例未执行。筛选结果只表述实际运行范围，保留编译、Linux 运行、最低基线和真实网络各自的证据。
3. 验证记录与工作报告的存放和引用按[《工作报告规范》](工作报告规范.md)执行。测试输出和证据使用脱敏数据。
