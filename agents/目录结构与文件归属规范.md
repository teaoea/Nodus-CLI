# Nodus CLI 目录结构与文件归属规范（MUST）

本规范负责源码、测试、文档、工具与本地材料的物理归属、命名及移动同步。模块职责和依赖边界遵循[《代码编写规范》](代码编写规范.md)。目录调整按当前任务范围实施，规划目录在有实际文件时建立。

## 一、目录与文件归属

| 位置 | 存放内容 |
| --- | --- |
| 仓库根目录 | `Cargo.toml`、`Cargo.lock`、`README.md`、`AGENTS.md`、`CLI.md`、`LICENSE` 和现有许可登记。命令的具体契约、用法和规划统一维护在 [CLI.md](../CLI.md)。 |
| `agents/` | 长期开发与协作规范。新增规范通过 [AGENTS.md](../AGENTS.md) 指向的专项入口登记。 |
| `src/` | `nodus` 二进制及 `nodus_cli` 库源码。进程入口、模块与分工见第二章。 |
| `tests/` | Cargo 集成与命令契约测试。按需要增加 `tests/fixtures/` 存脱敏的固定输入，`tests/support/` 存由多个测试复用的辅助代码。 |
| `notices/` | 第三方许可证原文、版权与来源材料。许可选择、登记与保留要求见[《依赖与许可证规范》](依赖与许可证规范.md)。 |
| `examples/` | 有实际使用需求时存放可运行的接入示例和脱敏配置。 |
| `tools/` | 有实际使用需求时存放开发、构建、检查及验证工具。 |
| `deployment/` | 启用相应部署任务后存放部署模板、服务单元及配套说明。 |
| `.local/` | 本地工作报告、修改意见和验证证据，具体位置与保留要求见[《工作报告规范》](工作报告规范.md)。 |
| `target/` | Cargo 默认的构建产物与缓存目录。 |

## 二、源码、测试与命名

1. `src/main.rs` 负责进程入口、调用装配和退出状态。 `src/lib.rs` 负责库模块声明及必要的入口导出。命令参数和执行编排归命令模块，结果渲染归输出模块，请求 Core 公开接口的转换归 Core 接入层。
2. L0 模块可沿用 `src/` 下的现有单文件布局。同一职责出现多个需要独立维护的部分时，再按职责形成子模块。后续守护进程、IPC 和 Linux 系统适配各自按实际职责归属，与命令输出及 Core 接入分开维护。Rust 模块声明、可见性和文件布局随实际调用边界调整。
3. 贴近实现的单元测试可使用同模块的 `#[cfg(test)]`。跨模块及面向调用方的测试归 `tests/`，按实际行为或契约命名，例如现有的 `test_l0_contract.rs`。固定夹具与运行生成的文件分开，测试生成内容使用临时目录或指定的本地证据目录。
4. 自有源码、脚本、模块目录按所属语言约定命名。Rust 和 Python 使用有明确职责的 `snake_case` 名称，现有 Cargo 入口文件、公开命令名称、部署文件及上游许可文件按自身契约维护。模块说明使用 Rust 文档注释，跨模块使用说明放在实际入口附近并由根 README 导航。

## 三、文件调整与同步

1. 新增、移动、改名或删除时，同步受影响的 Rust 模块声明、Cargo 目标与清单、脚本入口、测试及夹具路径、示例和文档链接。涉及公开命令或选项的调整遵循[《命令行与输出契约》](命令行与输出契约.md)。
2. 新增顶层目录或独立工具时，在根 README 或所属入口登记用途与实际使用方式。目录迁移保留有用的历史与验证证据，报告记录旧路径、新路径和待验证范围。
3. 纯目录变更核对实际引用、构建与测试入口及路径变化。运行范围和证据记录遵循[《Linux 构建与验证》](Linux构建与验证.md)，审查和交付按对应专项执行。
