# Nodus CLI 错误代码规范（MUST）

本规范负责进程退出码、宿主错误标识、Core 错误保留与映射。公开字段、退出码清单及用法见 [CLI.md](../CLI.md)，输出流与公开兼容规则见[《命令行与输出契约》](命令行与输出契约.md)。守护进程事务与结果确认见[《守护进程与本地控制规范》](守护进程与本地控制规范.md)。

## 一、退出码、宿主错误与 Core 错误

| 层次 | 权威定义与用途 |
| --- | --- |
| 进程退出码 | CLI 集中定义的 `ExitCode` 表达操作结果类别。退出 `0` 表示满足命令的公开成功条件。不同错误可归入同一非零退出类别，并保留结构化原因。 |
| 宿主错误标识 | CLI 集中定义错误来源和机器名称。宿主参数、路径、权限及 IPC 失败使用实际来源和稳定名称。CLI 自有错误优先使用符号标识；没有对应 Core 错误码时，机器字段 `code` 为 `null`。 |
| Core 错误码 | 锁定版本的 Core 是六位错误码及其参数语义的权威来源。收到 Core 错误时保留原始整数值及允许公开的结构化信息。 |

若既有契约允许宿主沿用 Core 已登记的标识，须保留实际来源。例如，L0 未启用能力的宿主拒绝可使用 Core 的 `Unsupported` 数值，`origin` 仍标为 `cli`。该值表示已登记语义的复用。

## 二、映射与传播

1. 根据结构化错误与实际失败阶段集中映射退出码。区分参数或用法错误、配置校验失败、实例不可达、权限拒绝、协议或能力不支持、超时或取消、实际操作失败及结果未确认。批量配置校验按公开契约选取退出类别，保留各条问题的原码、位置和截断状态。
2. Core 原码以可无损表示的整数保留。禁止按数字取模、重编号、截断或通过消息文本猜测类别。收到未识别的 Core 数字时，使用明确的通用失败映射并尽可能保留原值。无法可靠取得原码时，明示缺失。
3. 结构化错误说明实际 `origin`、`name`、`phase` 和 `exit_code`，并携带适用的 `code`、位置和允许公开的参数。`message` 供人阅读。机器错误中的 `exit_code` 与实际进程退出码一致。凭据、私钥、令牌及敏感配置按守护进程规范处理。
4. 分别保留主操作、传输、编码、写入和清理失败的实际后果。结果未确认时提供可用的查询方式，避免把确认丢失解释为未执行。输出失败不能把已提交的操作描述为已撤销。

5. 分别判断命令退出、操作是否提交，以及守护进程与节点的运行状态。查询无结果、正常取消、预期拒绝或既有部署已达要求时，按命令契约返回，在源头停止生成错误诊断。不得仅凭 `Err`、非零退出码或日志等级触发通用故障处理。Core 的业务结果按锁定版本的公开契约传递，保留其原始语义及表示。

## 三、登记、兼容与验证

1. 新增或变更宿主错误、映射或退出码时，注明实际触发阶段、原因、失败后果及机器表示，同步权威定义、[CLI.md](../CLI.md)、受影响的帮助和对应测试。对已发布契约的变更遵循既有兼容与弃用规则。
2. 用覆盖生产入口的断言核对实际退出码、错误来源与名称、Core 原码、配置问题及可选字段，并检查 stdout／stderr。适用时覆盖保留的旧行为、安全脱敏以及结果未确认与明确失败的区别。测试范围、执行与记录遵循[《测试规范》](测试规范.md)。
3. 涉及结果分类或隔离时，从实际命令或控制入口验证预期结果未进入错误诊断入口，真实宿主故障仍可定位原始原因和失败步骤。涉及共享实例时，核对未受影响的独立操作仍能实际完成。分别断言命令退出、操作提交和实例运行状态，适用时验证诊断不可用不改变业务结果。
